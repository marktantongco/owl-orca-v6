§1 · System at a Glance
One Router, Nine Hacks, 1044M
OWL-ORCA v6 merges the v4.9 ecosystem framework and the v5 installer into a single 2,888-line artifact that provisions a Python asyncio router plane, an embedded Tier-0 JSON taxonomy, a billing sidecar, and an optional defense egress tier. The two Next.js PWA planes of the v5 lineage (384M for :3002/:3003/:3004) are replaced by a 10M in-process classifier, and the ruflo swarm is demoted to external-only after it violated the memory cap. Every optimization from the speed-hack sheet ships as real code, not a placeholder: uvloop installs as the event loop policy, the radix trie is a flat 4KB array, and the StreamRacer cancels losing upstreams on first byte.
The memory ledger below is the default boot profile with the standard egress tier enabled. It totals roughly 1044M against the v5 equivalent path of 1418M to 2697M, a saving driven by five deliberate trims: the PWA plane (374M), the canary and swarm units (768M), the DPI bypass tier (148M), hydra-gate (128M), and nylon (5M). Each trimmed component remains available behind an explicit opt-in flag rather than being deleted, so the operator can re-arm any tier when the operating environment changes.

§2 · Boot Ladder
Dry-Run, Core-Only, Then Egress
The installer follows a strict three-rung ladder. The first rung is a pure plan review: the 24 steps are enumerated, every flag combination is resolved, and nothing touches the disk. The second rung boots the 768M core with the embedded Tier-0 taxonomy and proves all nine hacks through the in-process selftest. The third rung adds the defense egress tier. The DPI tier is not a rung on this ladder; it is a contingency bolted on later, only on evidence.
$ bash owl-orca-v6-unified-final-installer.sh --dry-run --with-all-egress
# plan review only — 24 steps enumerated, DPI skipped (F5), exit 0
$ bash owl-orca-v6-unified-final-installer.sh --core-only
# first boot: router+forward+kiro+mempalace-lazy, 768M embedded tier-0
$ bash owl-orca-v6-unified-final-installer.sh --with-all-egress
# full defense tier: freebuff + graftcp + hydra + nylon, ledger ~1044M
In a systemd-less environment the units are started directly through the venv interpreter. The verification battery used during tuning booted all four core services with setsid nohup, confirmed the four listening ports, drove the classifier, tripped the breakers, and proved the SIGHUP reload, all from a single invocation of the persisted script scripts/fresh_box_tuned_verify.sh.

§4 · Circuit Breaker Policy
Tuned Per Cost-Tier
The breaker is a lock-free state machine: a plain atomic failure counter and a time.monotonic() timestamp, mutated only on the single-threaded event loop with no await points inside the hot path. The tuning session differentiated the thresholds by tier economics, because the cost of locking out a provider is not uniform across the stack. Cheap upstreams have many alternatives, so a dead one should be cut fast and forgiven fast. Premium upstreams are scarce, so they deserve patience before a lockout. The expensive residential tier exists solely for 403 work, so it trips quickly and stays dark for five minutes to protect quota.
TierTripCooldownDecayRationale
cheap3 fails45s2Alternatives abound; recover fast
medium5 fails60s1Proven default from the live boot test
premium7 fails90s1Patient; lockout hurts the good models
expensive3 fails300s1Quota protection, anti-ban backoff
Two semantics matter during operations. First, breaker state intentionally survives a SIGHUP reload. The registry keeps its failure memory across config swaps, so a hot reload never forgets that an upstream was misbehaving. Second, threshold changes from a tuned providers.json apply to newly created breakers or after a restart; existing breakers keep the policy they were born with. The live proof during tuning showed the differentiation exactly: antigravity-free (cheap) opened at precisely three failures while nvidia-nim (medium) held CLOSED at three and would have tripped at five.
$ curl -s http://127.0.0.1:60001/healthz | python3 -c "import sys,json; print(json.load(sys.stdin)['hacks']['H4_breakers'])"
# {'kiro-free': ['CLOSED', 0], 'nvidia-nim': ['CLOSED', 3], 'antigravity-free': ['OPEN', 3]}
§5 · Animal Routing
Cost-Tier Mapping, v13-Tuned
The Tier-0 classifier maps every prompt to one of seven animal modes inherited from the smp5.1.1 doctrine, and each mode carries a cost tier that narrows the StreamRacer candidate pool. The v13 tuning fixed the routing gap that the boot battery exposed: rabbit previously keyed only on ideation words and silently swallowed every speed prompt into the owl default. Rabbit now keys on twenty speed and multiply tokens, ant gained the singular step alongside steps, and two collision-prone keys were removed: owl dropped post (it matched blog and HTTP posts) and ant dropped the ambiguous verb break. Classification latency held between 0.021ms and 0.037ms across the full battery, far inside the 5ms envelope, with every probe routed correctly on a fresh box.

The fallback ladder in the third column is declared in the rules JSON for the StreamRacer: when every breaker in a mode's home tier reads OPEN, the race degrades one rung instead of hard-failing the request. Volume modes route to the free upstreams, synthesis modes to the medium tier, and the two deep-reasoning modes reserve the premium pool with a medium-tier parachute. Keyword matching is token-exact against the radix trie, which means hyphenated key phrases never match — the text tokenizer splits on non-alphanumerics — so multi-word concepts are expressed as paired tokens such as cross plus field.

§6 · Daily Ops
Health, Reload, Selftest
The three routines below cover the daily loop. The health endpoint reports the hack status matrix, the breaker snapshot, and the LRU cache statistics in one call. The reload script performs the atomic-rename swap and raises SIGHUP, which re-reads the four config files without dropping a single TCP connection. The selftest asserts all in-process hacks, including the 1.87us radix lookup and the SSE field translation, and is safe to run against the live router.
$ /home/z/.owl-orca-v6/bin/orca-health-check.sh # 9-hack selftest
$ /home/z/.owl-orca-v6/bin/orca-reload.sh # SIGHUP, no TCP drop
$ curl -s http://127.0.0.1:60001/healthz | python3 -m json.tool
$ /home/z/.owl-orca-v6/bin/graftcp-wrapper.sh curl https://example.com # H9 egress proof
Config edits under a live router. Never edit promptc-os-rules.json or providers.json in place. Write to a temp file and os.replace() it into position, then send SIGHUP. The atomic inode swap is what protects IDE watchers and the reload path from torn reads — the same discipline the installer itself uses.
§7 · Escalation
When to Add the DPI Tier
The DPI tier is a contingency, not a default. It costs 148M of memory and three extra processes (mhrv-rs, mieru, GooseRelay) whose only purpose is to disguise traffic from nation-state packet inspection. On Philippine circuits that machinery is pure overhead. The gate criteria are strict and both must be true: every standard egress circuit must read OPEN in the breaker snapshot after real attempts, and a block must be confirmed on the wire with a connection-level symptom rather than a quota or auth error.
Evidence checklist before arming DPI
1. All breakers OPEN across cheap and medium tiers after live traffic.
2. curl through the egress chain fails with a connection reset or timeout, not 401/403/429.
3. The failure reproduces across at least two upstreams and two time windows.
Then and only then: --with-dpi-bypass (GooseRelay tunnel key via openssl rand -hex 32, quota 20k/day shared per Google account, reset midnight Pacific).
Hydra-gate and nylon carry their own activation logic, independent of DPI. Hydra earns its 128M only when Playwright automation is in play, because its six rotation modes and auth-stripping exist to keep browser sessions alive. Nylon earns 5M only when the forward proxy is absent — its ACL CIDR and mirror features duplicate what :60000 already provides, and SIGHUP re-exec makes it cheap to keep on standby rather than running.

§9 · Rebuild Chain
Edit, Rebuild, Audit
The installer is assembled from six part files and must be rebuilt through the chain below after any edit, so the delivered artifact never drifts from its source. The audit harness extracts all fifty-two embedded artifacts, compiles every Python module, parses every JSON document, verifies the port registry, and asserts all nineteen hack markers plus the ten merge fixes. A build that fails any of the fifteen checks does not ship.
$ cd ~/my-project/scripts && cat v6_part1.sh v6_part2.sh v6_part3.sh v6_part4.sh v6_part5.sh v6_part6.sh \
  > ~/my-project/download/owl-orca-v6-unified-final-installer.sh
$ bash -n ~/my-project/download/owl-orca-v6-unified-final-installer.sh
$ python3 scripts/audit_v6.py # expect 15/15 PASS
The tuning session left three persisted scripts in the same directory: tune_v6.sh for the JSON swaps and SIGHUP, core_boot_verify.sh for the boot battery, and fresh_box_tuned_verify.sh for the clean-install proof. They are the fastest way to re-validate any future edit against a live router, and each is safe to run repeatedly because the installer and the boot battery are both idempotent.
